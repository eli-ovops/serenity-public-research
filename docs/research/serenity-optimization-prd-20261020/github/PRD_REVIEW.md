# Serenity 优化 PRD 独立审查（2026-10-20）

范围：只读核对 `../PRD.md`、`../RESEARCH_FINDINGS.md`、历史审计 `../../serenity-complete-advice-audit-20261020/REPORT.md` 与 `EXIT_DECISION_PROTOCOL.md`，并对照本目录七个公开仓库固定 commit 的核读结论。未联网重做研究、未运行模型或代码、未触及账户。审查时 `../DATA_CONTRACT.md`、`../ACCEPTANCE_CASES.md` 尚未生成；以下是主文问题，后续若附件补齐应重新核对。

## 会改变验收的发现

1. **[P1] 请求式模式不能承诺无人发起时“下一常规盘前交付新图”。** `PRD.md:113` 将重大新事实后的替代图限定到下一常规盘前，而 `PRD.md:143` 明定当前仅在用户请求时运行、无 scheduler/service/monitor；历史审计 `REPORT.md:49-55` 的 RXRX/TSM 规则真空及 TSLA 延迟提醒正是这条链断裂。若事实在两次聊天间发布，P0 无法发现、处理或送达，也无法把到期未完成归咎于数据管线。建议把当前请求式验收写成“首次收到相关请求时识别旧图已过期、同次临时处置并给替代图/有期限缺口”；下一常规盘前 SLA 只属于未来另获授权且有真实运行回执的 P1。P0 报告应明确上次请求之后未覆盖的时间窗。

2. **[P2] 效果比较的“原持有政策”尚无可冻结定义。** `PRD.md:205-207` 要同起点比较“原持有政策、修订政策及基准”，但历史审计 `REPORT.md:22,43-57,65-67` 说明初始买入建议部分 UNKNOWN、旧盈利保护迟建、RXRX/TSM 旧图过期、POET 批次未执行。对这些案例不存在完整的事前“原政策”可机械回放；若回看时补规则会产生后见偏差。建议明确两类比较：历史故障案例仅做过程反事实/敏感性展示，不能报成未见样本净优势；前瞻从同一天冻结一个完整、具体、可执行的基线（例如按原版有效规则或定义清楚的 buy-and-hold），并记录数据缺口、费用及未成交。没有可冻结基线的标 `UNKNOWN`，不强算相对优势。

3. **[P2] P2 的前瞻检验不应被 P1 通知授权串行阻塞。** `PRD.md:209-219,239` 将 P1 主动提醒排在 P2 前并以“P0+获授权后的P1”定义产品实施完成；同时 `PRD.md:227` 承认 P1 所需后台/接收端尚无授权。策略政策可在 P0 请求式运行中先冻结与前瞻记录，通知触发/送达率必须留给 P1 单独验收。否则一旦用户保留 research-only 禁后台边界，连低风险的研究政策有效性检验也被不必要地无限推迟。建议在阶段表写明 P2 可与 P1 独立启动、分报策略质量与通知质量，不能用请求式结果冒充持续监测成果。

4. **[P2] “缺总资金不输出个性化股数”与现仓目标剩余数交付需划清适用范围。** `PRD.md:58` 正确说缺总资金仅使账户比例 UNKNOWN，`PRD.md:92` 却笼统写“缺必要账户事实……不输出个性化股数”，而 `PRD.md:115` 要求每批 `latest_confirmed_quantity→target_remaining_quantity`；历史审计 `REPORT.md:57` 要求纠正 POET 20 股第一批未执行后终局目标。若已由用户确认现仓 20 股，但总资金未知，实施者可能据第 92 行拒绝给明确终局数量，重现原故障。建议明确：新建仓/加仓的账户比例、计划损失与个性化股数仍待资金；已有仓减仓/退出可以基于用户已确认数量给研究层目标剩余数，同时标账户层 UNKNOWN、最终交易由用户决定。若现仓数量也未知，则目标数量 UNKNOWN 并问最小必要事实。
